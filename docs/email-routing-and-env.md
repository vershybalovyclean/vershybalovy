# Корпоративная почта: маршрутизация, переменные окружения, проверка (13.10.2026)

Google Workspace: один ящик `kontakt@vershclean.pl` и алиасы `partnerzy@`, `biuro@`, `reklamacje@` (фильтры Gmail раскладывают их по ярлыкам).

## Схема: источник → обработчик → получатель

| Источник | Обработчик | Получатель |
|---|---|---|
| Заказ уборки (календарь, `booking.js`), калькуляторы, быстрые формы | `api/submit.js` → Resend, Telegram, Supabase, Google Sheets | env `to_email` = `kontakt@vershclean.pl` |
| Партнёрская форма `/program-partnerski#dolacz` | `api/submit.js`, ветка `formType: "partner"` → Resend, Telegram | env `partner_to_email`, по умолчанию `partnerzy@vershclean.pl` |
| Ссылки `mailto:` в подвалах, контактные блоки, JSON-LD | статический HTML | `kontakt@vershclean.pl` |
| Партнёрская страница (строка под формой, кнопка после отправки) | статический HTML | `partnerzy@vershclean.pl` |
| Рекламации, бухгалтерия | отдельных форм на сайте нет | `reklamacje@`, `biuro@` используются только в юридических текстах, если их там укажут |
| Письма Supabase Auth (приглашения, сброс пароля) | Supabase SMTP через Resend | отправитель `noreply@mail.vershclean.pl` (не меняется) |

Ссылки на корпоративные адреса помечены `data-vc-fixed-mail`: скрипт `site-texts-sync.js` не заменяет их значением `contact_email` из Supabase. Сейчас в Supabase `contact_email = vershybalovy@gmail.com`, без атрибута скрипт вернул бы личный адрес в подвалы. Значение настройки в админ-панели можно позже заменить на `kontakt@vershclean.pl`: для остальных (не помеченных) ссылок это сработает автоматически.

## Переменные окружения Vercel (проект сайта)

Имена чувствительны к регистру. Значения секретов в переписку не отправлять.

| Переменная | Нужна | Что делает | Рекомендуемое значение | Если не задана |
|---|---|---|---|---|
| `Resend_api_key` | да, для любой почты | ключ API Resend (секрет) | ключ с правом только отправки (Sending access) | письма не уходят, остальные каналы работают, ошибок нет |
| `to_email` | да, для писем о заказах | получатель писем о заказах | один адрес: `kontakt@vershclean.pl` (без запятых и пробелов) | письма о заказах не отправляются, остальные каналы работают |
| `resend_from` | рекомендуется | отправитель писем о заказах | `Vershy Property Care <noreply@mail.vershclean.pl>` | используется `onboarding@resend.dev` (тестовый отправитель Resend, доставляет только на адрес владельца аккаунта Resend) |
| `partner_to_email` | нет | получатель партнёрских заявок | `partnerzy@vershclean.pl` | то же значение по умолчанию |
| `partner_from_email` | нет | отправитель партнёрских писем | `Vershy Property Care <noreply@mail.vershclean.pl>` | то же значение по умолчанию |
| `supabase_url`, `Supabase_anon_key` | существующие | запись заказа, Telegram, push | не менять | заказы не сохраняются |
| `GOOGLE_SHEETS_WEBHOOK_URL` | существующая | журнал заявок в Google Sheets | не менять | запись в Sheets пропускается |

Проверено на тестовом стенде (подмена `fetch`, без реальных отправок): при отсутствующих или пустых необязательных переменных код не бросает исключений и использует значения по умолчанию. Если нет ключа Resend, партнёрская заявка уходит только в Telegram (ответ сайта «успех»), а если нет ни одного канала, ответ сервера 500 и сообщение об ошибке на странице.

## Как проверить, что домен отправителя подтверждён в Resend

1. Войдите в Resend под аккаунтом, которому принадлежит ключ, указанный в Vercel как `Resend_api_key`. Если аккаунтов несколько, откройте в Vercel имя переменной (значение не показывайте) и сравните с именами в Resend → API Keys.
2. Resend → Domains → `mail.vershclean.pl`: статус должен быть **Verified**, записи SPF и DKIM (и DMARC, если задана) зелёные.
3. Если домен виден в другом аккаунте или статус не Verified, письма от `noreply@mail.vershclean.pl` будут отклонены (в логе Resend → Emails статус Failed, причина «domain is not verified»).
4. Для сайта удобнее отдельный ключ: Resend → API Keys → Create → Sending access, домен `mail.vershclean.pl`. Заменить его в Vercel вы делаете сами.
5. После деплоя отправьте тестовую заявку (имя «TEST …») и откройте Resend → Emails: должна быть запись со статусом Delivered, получатель `partnerzy@vershclean.pl` (или `kontakt@vershclean.pl` для заказа).

## Что проверить вручную в Vercel

- Settings → Environment Variables: все переменные из таблицы заданы для окружения Production (и Preview, если проверяете ветку); имена совпадают по регистру.
- `to_email` содержит ровно один адрес `kontakt@vershclean.pl`.
- Добавлены `resend_from` и, при желании, `partner_to_email` / `partner_from_email`.
- После изменения переменных нужен новый деплой: в уже собранном деплое они не обновляются.
- Preview-деплои закрыты паролем (`STAGING_USER` / `STAGING_PASS`, `middleware.js`): для тестов Preview-ветки они нужны, в Production не действуют.

## Что проверить вручную в Gmail после тестовых заявок

| Тест | Тема письма | Ожидание |
|---|---|---|
| Партнёрская форма (имя «TEST …») | `Nowe zgłoszenie partnerskie — Vershy Property Care` | пришло в ящик `kontakt@`, ярлык «Сотрудничество» (фильтр по получателю `partnerzy@`), «Ответить» адресует email из формы |
| Быстрая форма/заказ с пометкой TEST | `Nowe zgłoszenie od TEST …` | пришло, получатель `kontakt@`, «Ответить» адресует email клиента (если указан) |
| Письма не в спаме, нет дублей | — | одно письмо на заявку |

Доставку нельзя считать подтверждённой по ответу API или логу отправки: нужна запись в Resend → Emails и письмо в Gmail.

## Замечания

- `info@vershclean.pl` используется как контакт VAPID для push (`supabase/functions/send-push`, переменная `VAPID_SUBJECT` в Supabase). В схему адресов он не входит, меняется отдельно.
- Юридические тексты (`regulamin.html`, `polityka-prywatnosci.html`) не менялись: личный адрес в них остаётся, пока не согласованы изменения по разделам. Ссылки в тексте политики приватности помечены `data-vc-fixed-mail`, чтобы их не подменяла синхронизация.
