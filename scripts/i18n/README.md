# Языковые версии сайта (UK / RU / EN) — как они создаются

Каталог `scripts/i18n/` — локальные инструменты. Он исключён из деплоя (`.vercelignore: /scripts/`, `vercel.json: /scripts/:path* → /`),
на сайт попадают только результаты: `uk/`, `ru/`, `en/` (sitemap.xml — отдельным шагом).

## Источники переводов (единственные)
| Что | Где |
|---|---|
| Тексты страниц услуг (меню, контент, формы, FAQ, калькуляторы) | словари внутри польских страниц (`SL(lang)`, `TX`, `pl:{…}`) — не дублируются |
| meta description / og:description / JSON-LD (name, serviceType, description, areaServed) | `scripts/i18n/seo.js` (`SEO`) |
| title, og:title | берутся из словарей страницы (как их показывает `SL(lang)`) |
| Юридические страницы (Regulamin, Polityka prywatności, Polityka cookies, Załącznik nr 1) | `scripts/i18n/legal/*.js` (блоки по порядку) + `LEGAL_META` в `seo.js` |
| Шапка/подвал юридических страниц | берутся из уже сгенерированных страниц услуг того же языка + `EXTRA` в `prerender.html` |

## Порядок сборки (всё локально, без Node и без GitHub Actions)
1. Запустить статический сервер репозитория (`.claude/launch.json → static-site`, порт 8080) и приёмник файлов: `powershell scripts/i18n/receiver.ps1` (localhost:8090, пишет **только** в `uk/ ru/ en/`).
2. Открыть `http://localhost:8080/scripts/i18n/prerender.html`, в консоли: `runAll(['uk','ru','en'])` — 8 страниц × 3 языка; затем `runLegal(['uk','ru','en'])` — 4 юридические страницы × 3 языка.
3. `sh scripts/i18n/build-sitemap.sh` — собрать `scripts/i18n/sitemap.multilang.xml` (8 страниц × 4 языка с hreflang). Рабочий `sitemap.xml` остаётся прежним (только польские URL) и заменяется им ОТДЕЛЬНЫМ шагом после проверки Production (см. PREVIEW-CHECKLIST.md, раздел 6).
4. Открыть `http://localhost:8080/scripts/i18n/check.html`: `runChecks()` и `runLegalChecks()` — автоматические проверки (lang, title, description, canonical, hreflang, JSON-LD, битые ссылки/ресурсы, относительные пути, дубли id, остатки польского, паритет цен и чисел с польской страницей).
4b. Сводка юридических переводов для проверки: `buildLegalReview()` → `scripts/i18n/review/legal-review.html` (PL рядом с UK/RU/EN).
5. (по желанию) `powershell scripts/i18n/devserver.ps1` — порт 8091, имитирует `vercel.json` (cleanUrls, rewrites, 404 с настоящим статусом) для ручной проверки.

## Как работает генератор
Польская страница загружается в скрытый iframe, выполняется её собственный `SL(lang)`; переведённые тексты и атрибуты переносятся в исходный DOM,
затем подставляются `html lang`, title/description/OG, canonical, hreflang (pl/uk/ru/en/x-default), JSON-LD, языковые ссылки переключателя (`<a href>`),
внутренние ссылки, корневые пути ресурсов. Страница остаётся **статическим HTML**: весь перевод виден без JS.

## Защита от устаревших переводов
* Страницы услуг: переводы живут в самих страницах; повторный запуск генератора всегда берёт актуальный польский исходник.
* Юридические страницы: в каждом `legal/*.js` записан `plHash` — отпечаток польского текста. Если польский документ изменился, генератор
  останавливается с сообщением «ПЕРЕВОД УСТАРЕЛ» (или «блоков перевода N ≠ польских M»). Числа/суммы каждого блока сверяются с польским оригиналом.
  После обновления перевода: поставить `plHash: '__HASH__'`, запустить `runLegal` — в логе появится новый хеш, вписать его.

## Что нельзя менять без согласования
Цены, нормы времени, калькулятор, API, GTM/GA4/Ads, политика Cookie Consent, юридические условия. Генератор их не изменяет (паритет цен проверяется автоматически).
